# Changelog

`@manyoars/pool` is private (the hosted pool); this file records what changes for its callers.

## Unreleased

- `sample-pack --skeleton-only` builds a release with no transcript text: manifest rows with `transcripts: 0`, `sessions/<match id>/skeleton.json`, `census.json`, `pack.json`, and a `README.md` data card (`license: other` with the rights link, the `agent-traces` tag, the validate command, the lots page) written from the build's own `pack.json` and `census.json`. `--older-than <days>` (default 30 with `--skeleton-only`) keeps out a session whose last line is newer, or has no date, counted `fresh`; `--exclude-manifest <path>` leaves out every session an earlier lot's manifest holds, found through `index.jsonl`, counted `inExcludedLot`, and stops when a match id is not in the index. `validate-pack` now accepts `transcripts: 0` (the row must name its skeleton) and a root `README.md` only when every row says 0 (a pack that mixes 0 rows with transcript rows is refused). Nothing is uploaded.
- `validate-pack` accepts `acceptedAt` on a deposit row (a time, and only beside a `depositor:<16 hex>` owner) and `docs/session-record.md` lists it, so a pack from `sample-pack --deposits` validates; `license-status` prints the covenant version and `acceptedAt` of a deposit row, read from its manifest row. `validate-pack` now also refuses a file or folder at the pack root or a file directly under `sessions/` that no row names, and a depositor row whose `sourceLicense` is not a covenant, so a pack that passed before can newly fail.
- The pool operator can print the proof sheet (`queries/proof-sheet.sql`: installs, accepted accounts, accounts still depositing at 4 weeks, counting sessions by harness, and served cells, each with an as-of day), and the covenant funnel now splits `accepted`, `depositing_4w`, and the raw-yes share by request country, folding a country with fewer than five accounts into `other`.
- `sample-pack --deposits <folder>` builds a pack from the folder `pull-deposits` wrote: each Raw Copy is captured into a throwaway store, paired with its deposit row, and written as a row with a `depositor:<16 hex>` owner (an HMAC of the account under the buyer key), the covenant license, and `acceptedAt`. Unlinked copies, tier `none`, protected regions, and accounts with no proved acceptance are counted under `deposits` and left out; the pulled folder is never written. `pull-deposits` now reads in pages of 25.
- The pool's operator can copy the eligible third-party deposits out of the pool into a local folder (`npm run pull-deposits -w packages/pool -- --out <folder outside every repository>`): each account's proved covenant acceptances, each deposit with its `counted_at`, and each Raw Copy not erased. It leaves out restricted accounts, accounts with no raw yes in force, accounts with no proved acceptance, and erased rows, and it only reads the pool.
- The pool's operator can record that a recipient was told to erase a withdrawn row and that it confirmed (`npm run notices -w packages/pool -- sent|confirmed <match id> --recipient <name> --operator <folder>`, or `--ids <file>`; `docs/pool.md`, "Erasure notices"). The notices go in an append-only `notices.jsonl` beside the owners file, one line per recipient and match id, and a confirmation is a second line, never an edit; the command refuses a match id with no delivery to that recipient and a confirmation with no notice, and `confirmed --at <date>` records the day a recipient replied. `license-status` reads the register: `erasure` is `notice-sent` or `confirmed` with its date at each recipient, `unknown` while no notice is recorded for a withdrawn row, and it now refuses a pack folder it cannot read without printing the path.
- `sample-pack` and `deliver` take `--buyer-key-file <path>`, which reads the buyer key from a file (a leading byte order mark and trailing whitespace trimmed) so the key is in no process's arguments, npm debug log, or `builds.jsonl`; both refuse, with a one-line message that never holds the key, when `--buyer-key` is also given or the file is missing or empty. `--buyer-key` is unchanged. `docs/pool.md`, "The sample pack".
- The pool's operator can ask what license state a sample pack row is in (`npm run license-status -w packages/pool -- <match id> --key-id <id> --operator <folder> [--json]`, or `--ids <file>`; `docs/pool.md`, "License status by match id"). For each match id under one buyer key id it reads `index.jsonl`, `deliveries.jsonl`, `objections.jsonl`, and the pack folders the index names, and prints the lots the row was built into with their terms, each recipient with its license and date, and whether an objection has withdrawn it (`built`, `delivered`, `withdrawn`, or `unknown`). The covenant version, and the erasure at a recipient of a delivered row that was withdrawn, read `unknown` because no operator file records them yet. It writes nothing, takes a key id and never a key, and prints no session id, owner, project folder, objector's name, or key.
- The session record and the pack manifest have a public spec and a validator (`docs/session-record.md`, spec version 1; no pool migration). `npm run validate-pack -w packages/pool -- <pack folder | manifest.jsonl | record.json>` checks every field, its type, and whether it is required, and refuses an unknown field, a raw id, and a plain digest. It exits 0 when the input conforms, and 1 with one line per violation (where, field, rule; never a value). It reads files only: no key, no network, no account. A test holds the page equal to the writer's fields, and the sample pack's tests build packs the validator accepts.
- The sample pack keeps an objection out and records the hand-over (lot 1, no pool migration). `objections.jsonl` beside the owners file names a session or a person: `sample-pack` leaves out each session it names, and each whose text holds the name before or after redaction, counted `objected` in `pack.json` (which now also holds `keyId`, the first 16 hex of the buyer key's SHA-256, and `objections`, the SHA-256 of `objections.jsonl` as read). `npm run deliver -w packages/pool` appends one row per session per recipient to `deliveries.jsonl`, skips a (recipient, lot, match id) already recorded, refuses a pack built under other objections than the file holds now, a repository folder, and a wrong buyer key, and sends nothing; `deliver recipients <session or name>` prints each recipient with its match id (Art. 15(1)(c), 19, 21(1)). `docs/pool.md`, "The sample pack".
- The sample pack can carry a repository pointer and an outcome block for an owner who sets `"pointer": true` in the owners file (default false; with no opt-in no git call is made and nothing is written). `pointer` is the `origin` remote (credentials dropped) and the newest commit from before the session began on its own branch, else `origin/<branch>`, else `origin/HEAD`, never `HEAD`; a working directory that no longer exists maps to the repository it sat in, and one that cannot be found, or whose remote is a local path, names an account, or holds a key shape, reads `pointer: null` and is counted `noPointer` in `pack.json`. `outcome` holds the last prompt's `verify` and each commit the session made with whether the remote's default branch holds it now. Git runs through an injected runner (`PackOptions.git`). `docs/pool.md`, "The sample pack".
- The sample pack carries each session's skeleton and a census. `sessions/<matchId>/skeleton.json` is the pool deposit's own skeleton for the session (error codes, the call after each failure, human interventions, and frames, in the wire's vocabulary and under its gate) with `id` set to the match id and every `repoKey` rewritten under the buyer key, so no store key reaches a buyer and two buyers cannot join on a repository; a tool's `digests` are dropped and each `merkleRoot` and the `timingPrint` re-derived under the buyer key, so the skeleton holds no unkeyed hash of content or timing. `manifest.jsonl` rows gain `models`, `turns`, and `skeleton`; `census.json` counts the sessions by harness, harness version, model, error code, recovery, intervention, prompt class, and turn bucket, with no row or id of a session; and `pack.json` counts `noSkeleton` for a session the store holds no skeleton of. `docs/pool.md`, "The sample pack".
- The pool's operator can build an evaluation sample pack for one recipient, offline, from a copy of a local session store (`npm run sample-pack -w packages/pool`; `docs/pool.md`, "The sample pack"). A session is left out when its main or any subagent transcript holds an exclusion term or it has no raw to scan (checked first), or when no owners entry or harness terms row states its rights. Each written transcript has its injected system prompt, CLAUDE.md bodies, and memory index replaced by keyed markers and is redacted as a deposit is. `manifest.jsonl` gives each session its owner, source license, harness terms, permitted uses (evaluation, benchmarking, and task design; training is not offered for Claude Code or Codex), and an opaque match id, an HMAC under the recipient's key of the session's key in the operator's matching index. No session id, line uuid, or request id reaches the pack: each is rewritten under the same keyed index, and the map from session id to match id stays in the operator's `index.jsonl` beside the owners file. The pack is built in `<folder>.partial` and renamed when the run finishes. Nothing is uploaded, and the output folder must be outside every git repository.
- The sample pack takes only accepted sessions: a session needs `--min-turns` turns (default 20), a recorded repository, and no longer twin that replays its first prompt, and one whose redacted text still holds a key shape is dropped before anything is written; each rule is counted in `pack.json`, which also records `bytes` and `elapsedMs`. The pack refuses an owners file inside a git repository.
- The sample pack's redaction is version 4: injected text in a system request blob and a memory-file edit is marked like its attachment copy, the account each repository's `origin` lives under is `<owner>`, tool use ids are keyed so a call and its result pair, token counts, scoped npm names, and `1password:` are no longer masked, synthetic token fixtures are, a host a session fetched stays in that call's result, and an orchestration lead session (`/loop /orchestrate`, `/orchestrate`, or a prompt an owners entry lists under `leadPrompts`, such as `/handoff resume`) is not drawn (counted `lead` in `pack.json`).
- The sample pack takes a Codex session whose rollout is the only copy: the exclusion check reaches the rollout through the Codex source, so the session is scanned and packed instead of left out as having no raw. Its `<user_instructions>`, `<environment_context>`, and AGENTS.md text become keyed markers, and its session id and call ids are rewritten under the keyed index as Claude Code's ids are. The harness terms rows are OpenAI's Terms of Use (effective 2026-01-01) and Usage Policies (effective 2026-11-20) for Codex, and the Claude Code row now names Anthropic's Usage Policy as effective 2026-11-12, the date the page prints. Training is not offered on either. A resumed session (Claude Code or Codex) is a duplicate when it shares a repository and the first three things the person typed with another (one list the start of the other), whatever its timestamps, uuids, and session id. Lines the harness wrote (an `isMeta` line, a slash command's caveat, name, and output, a tool result) are skipped, so unrelated sessions that open with the same slash command, or with `continue`, are both kept. The check reads each session's first typed turn before any other rule, so a session the draw never reaches is not gated. The secret scan also leaves out a Read's image copy under `toolUseResult.file.base64`.
- Boards are braked (migration `0037`): per account, the 11th wrong club code in a rolling hour and the 6th club created in a rolling day are 429 `rate_limited` with `retry_after`, and a parallel burst cannot pass either limit. The attempts are in the account export and removed by `erase account`.
- A nickname is NFKC-normalized, 2 to 24 letters (combining marks included), digits, space, `-`, `_`, or `.`, with no edge space, `@`, or web address, else 422 `nickname_invalid` (was `bad_nickname`).
- `npm run hide-nickname` lets the operator remove a member's nickname and records who and why (`club_hides`, in the account export and removed by `erase account`).
- Boards: per-account weekly counts (`account_weeks`, migration `0036`), private clubs joined by a code (`POST /v1/clubs`, `POST /v1/clubs/join`, `GET /v1/clubs/:id`, `DELETE /v1/clubs/:id/me`, `GET /v1/clubs/consent`), and a public open board (`GET /v1/board`) that lists an account after 90 days of standing or a hand grant (`npm run grant-standing`). Ranked by weeks rowing, then active days; tokens and cost are never held or ranked. See `docs/pool.md`, "Boards".
- Rights: the operator can give a confirmed requester their export and record their raw-consent withdrawal when the requester cannot use the client. `npm run erase -w packages/pool -- export --account <id> --out <folder> [--raw] [--local]` writes the same `account-export-NNNN.json` pages `oars pool export` returns (one shared page builder), and `erase withdraw --account <id> [--confirm] [--local]` runs the same update the route runs (`WITHDRAW_RAW_CONSENT`) and drops the account's staged raw parts. See `docs/pool-rights.md`.
- The pool deploys itself: `.github/workflows/deploy-pool.yml` applies every unapplied D1 migration and deploys the Worker after each passing `ci` run on `main`, tags the Worker version with the commit, and reads the live pool as a smoke check. `docs/pool.md` says where to read the deployed commit.
- `sample-pack --strip-thinking` builds a lot with no model reasoning: it removes every `thinking` and `redacted_thinking` block (text, signature, encrypted data) and every Codex reasoning item from the delivered transcripts, keeping the line of a message that held only thinking with empty content. `pack.json` and each manifest row carry `reasoning: "stripped"` or `"kept"` (optional in `docs/session-record.md`); the thinking-token count in the skeleton stays (`docs/pool.md`).
