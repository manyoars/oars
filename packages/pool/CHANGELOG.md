# Changelog

`@manyoars/pool` is private (the hosted pool); this file records what changes for its callers.

## Unreleased

- The pool's operator can build an evaluation sample pack for one recipient, offline, from a copy of a local session store (`npm run sample-pack -w packages/pool`; `docs/pool.md`, "The sample pack"). A session is left out when its main or any subagent transcript holds an exclusion term or it has no raw to scan (checked first), or when no owners entry or harness terms row states its rights. Each written transcript has its injected system prompt, CLAUDE.md bodies, and memory index replaced by keyed markers and is redacted as a deposit is. `manifest.jsonl` gives each session its owner, source license, harness terms, permitted uses (evaluation, benchmarking, and task design; training is not offered for Claude Code or Codex), and an opaque match id, an HMAC under the recipient's key of the session's key in the operator's matching index. No session id, line uuid, or request id reaches the pack: each is rewritten under the same keyed index, and the map from session id to match id stays in the operator's `index.jsonl` beside the owners file. The pack is built in `<folder>.partial` and renamed when the run finishes. Nothing is uploaded, and the output folder must be outside every git repository.
- The sample pack takes only accepted sessions: a session needs `--min-turns` turns (default 20), a recorded repository, and no longer twin that replays its first prompt, and one whose redacted text still holds a key shape is dropped before anything is written; each rule is counted in `pack.json`, which also records `bytes` and `elapsedMs`. The pack refuses an owners file inside a git repository.
- The sample pack's redaction is version 4: injected text in a system request blob and a memory-file edit is marked like its attachment copy, the account each repository's `origin` lives under is `<owner>`, tool use ids are keyed so a call and its result pair, token counts, scoped npm names, and `1password:` are no longer masked, synthetic token fixtures are, a host a session fetched stays in that call's result, and an orchestration lead session (`/loop /orchestrate`, `/orchestrate`, or a prompt an owners entry lists under `leadPrompts`, such as `/handoff resume`) is not drawn (counted `lead` in `pack.json`).
- The sample pack takes a Codex session whose rollout is the only copy: the exclusion check reaches the rollout through the Codex source, so the session is scanned and packed instead of left out as having no raw. Its `<user_instructions>`, `<environment_context>`, and AGENTS.md text become keyed markers, and its session id and call ids are rewritten under the keyed index as Claude Code's ids are. The harness terms rows are OpenAI's Terms of Use (effective 2026-01-01) and Usage Policies (effective 2026-11-20) for Codex, and the Claude Code row now names Anthropic's Usage Policy as effective 2026-11-12, the date the page prints. Training is not offered on either. A resumed session (Claude Code or Codex) is a duplicate when it shares a repository and the first three things the person typed with another (one list the start of the other), whatever its timestamps, uuids, and session id. Lines the harness wrote (an `isMeta` line, a slash command's caveat, name, and output, a tool result) are skipped, so unrelated sessions that open with the same slash command, or with `continue`, are both kept. The check reads each session's first typed turn before any other rule, so a session the draw never reaches is not gated. The secret scan also leaves out a Read's image copy under `toolUseResult.file.base64`.
- Boards are braked (migration `0037`): per account, the 11th wrong club code in a rolling hour and the 6th club created in a rolling day are 429 `rate_limited` with `retry_after`, and a parallel burst cannot pass either limit. The attempts are in the account export and removed by `erase account`.
- A nickname is NFKC-normalized, 2 to 24 letters (combining marks included), digits, space, `-`, `_`, or `.`, with no edge space, `@`, or web address, else 422 `nickname_invalid` (was `bad_nickname`).
- `npm run hide-nickname` lets the operator remove a member's nickname and records who and why (`club_hides`, in the account export and removed by `erase account`).
- Boards: per-account weekly counts (`account_weeks`, migration `0036`), private clubs joined by a code (`POST /v1/clubs`, `POST /v1/clubs/join`, `GET /v1/clubs/:id`, `DELETE /v1/clubs/:id/me`, `GET /v1/clubs/consent`), and a public open board (`GET /v1/board`) that lists an account after 90 days of standing or a hand grant (`npm run grant-standing`). Ranked by weeks rowing, then active days; tokens and cost are never held or ranked. See `docs/pool.md`, "Boards".
- Rights: the operator can give a confirmed requester their export and record their raw-consent withdrawal when the requester cannot use the client. `npm run erase -w packages/pool -- export --account <id> --out <folder> [--raw] [--local]` writes the same `account-export-NNNN.json` pages `oars pool export` returns (one shared page builder), and `erase withdraw --account <id> [--confirm] [--local]` runs the same update the route runs (`WITHDRAW_RAW_CONSENT`) and drops the account's staged raw parts. See `docs/pool-rights.md`.
- The pool deploys itself: `.github/workflows/deploy-pool.yml` applies every unapplied D1 migration and deploys the Worker after each passing `ci` run on `main`, tags the Worker version with the commit, and reads the live pool as a smoke check. `docs/pool.md` says where to read the deployed commit.
