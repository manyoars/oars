# Changelog

All notable changes to `@manyoars/oars`. Versions follow semver; a release is the tag `cli-v<version>`.

## Unreleased

- `oars sessions` cells and the pool's stored cells are now weekly, except a `live` cell: a cell is keyed on the Monday of its UTC week (`grain: week`), and a one-step shape motif with a known day also keeps a day cell (`grain: day`) for the reads of days (`live`, tool-day, day move, call shape), each of which now reads day cells alone, while every read of weeks reads week cells alone. A window of two or more steps has week cells only, so recovery finds the step after a failed call in the week cell and the failed call itself in a day cell. `effort` leaves the frame bucket: `fit` and `interaction` no longer slice by effort (interaction no longer holds it constant, so it stays a stated confounder), and the one cell that holds effort pairs it with the bucket of the thinking tokens and joins no model or version. The `adoption` and `change` reads state weeks, not days: `firstWeek`, `lastWeek`, `weeks`, and `weeksSinceLast` (`adoption`), and `firstWeek` and `lastWeek` (`change`, and `fromLastWeek` and `toFirstWeek` on a version boundary), each week named by its Monday. Every cell id and every pool version changes, and a stored `cells.jsonl` without `grain` is derived again on the next read. The pool takes migration `0008_cell_grain.sql`.
- `oars sessions` now floors a recall step's token count to its bucket where the step enters a local cell, as every other count in a cell already was, so no cell holds an exact number.
- `oars pool deposit` builds the pool's local deltas: it compares your own before and after windows (7 days each, at least 5 sessions a side, counted over sessions that passed the session gates and have ended) and the batch of the session that fills the after window carries each change once in `deltas`: a plugin `added` or `removed` (as `private`), a `permissionMode` or `effort` `changed` by field name alone, or a public `package` `removed`, each with one signed, bucketed change and no session id, root, date, or exact value. A delta is marked in `deltas-sent.log` in the outbox folder after its batch is written, so a stopped deposit builds it again and a rebuilt batch carries none it already marked (an unsent batch rebuilt later drops its delta). `oars pool outbox --explain` shows a row for each field, and the outbox folder changes with the field list, so batches built before are discarded as stale. Nothing is sent.
- Local deltas keep their once-only mark when the sessions ready change: windows sit on a fixed grid from the epoch and the mark names the after window's place on it, not the session that filled it. A plugin is compared only over sessions of a harness that records plugins (Claude Code), a Read of part of a manifest never says a package was removed, and the after window is read as its first five sessions.
- Review lows closed: `oars gate hook` prints a block label once when one name is named twice in a call (the call is still denied); `oars pool fetch` with no `--harness` checks the sign-in before it reads the local store or prints its choice line; `oars pool deposit` sends `<literal>` for a stored MCP tool its server no longer lists, in place of the pool refusing the whole session; and `oars sessions` messages no longer cite an internal rule label.
- `oars sessions deposit --allow vscode-copilot` reads the chat sessions VS Code Copilot Chat writes (Stable, Insiders, and OSS builds; the `.json` and `.jsonl` forms) into the same store, with `recall`, `measure`, `books`, and `verify` reading them like any other harness. It is a different surface from the Copilot CLI source, opt-in like Cursor and Codex, and written from VS Code's public source and synthetic fixtures; it has never run against a live store, and an extension-written session carries no per-model input figure, so `input` 0 there means not known. A new source takes no capture version.
- `oars sessions` reads a rotated Copilot log: the archives `events.N.jsonl` beside the live `events.jsonl` are read oldest first with it as one session, each event once (a rotated head's replayed `checkpoint` events and any repeated event id are dropped when an archive is present). A session with archives changes its cursor and is read again at the next deposit; a session without them is unchanged, so the capture version stays 17.
- `oars sessions` capture version 17: a Gemini CLI session that ran on Windows (its own context turn says `win32`, or, with none, its working directory is a drive-letter or UNC path) stores its shell calls as `PowerShell` with the frame's `shell` `powershell`, as the CLI runs PowerShell there; Linux and macOS sessions are unchanged. A Gemini session in a project folder named for a hash of its path (from before the slug registry) now gets the cwd that hash matches (a workspace directory its chat lists, another folder's marker, or a `projects.json` key), and one it cannot match keeps none. Gemini sessions under `~/.cache/.gemini` (`SANDBOX=sandbox-exec`) are now read. The opt-in telemetry outfile stays unread by choice. A version-16 store's next deposit captures every transcript again.
- `oars pool deposit` now sends one spelling for a name the pool has no row for: an MCP server, skill, host, pull name, and native tool name off the public lists go as `private`, and `<literal>` is refused in those places. A step whose program has left the public list goes as `private` with no pull, so the batch parses. A batch built under an older vocabulary, field list, or skeleton format is not sent as it stands: the next deposit builds the session's batch again and removes the older file under its key, and until then `oars pool outbox` still prints it. A pull's version beside a masked package name goes as `<literal>`, an MCP tool beside a masked server goes as `<literal>`, and a native tool name off the table goes as `private`. A deposit now removes a session's earlier batch as soon as that session fails a gate, not at the end of the pass, and `oars pool outbox --explain` words its rows to match.
- `oars sessions` capture version 16 stores a call the user refused as a failed call with `errorCode` `user-rejected`, as Claude Code does. Cursor: a call whose per-call decision (`toolFormerData.userDecision`) is `rejected`. Codex: a shell call, patch, or command item that is `declined` with the user's refusal text (`exec command rejected by user`, `patch rejected by user`), which stored no outcome before; any other `declined` call stays unsettled. Gemini: a call the user cancelled or denied (`User cancelled tool execution`, or `Reason: User denied execution.`, `User cancelled operation`, or `Operation cancelled by user` at the confirmation prompt), which stored `errorCode` `other`; `Operation cancelled.` names no user and stays `other`. Each such call gains an error-line record (the refusal text) where it had none, and a session whose result line is new has a different `lines` count and skeleton. An accepted, absent, or unrecognized Cursor decision changes nothing and is not stored. A Grok plan-mode refusal and a Codex `write_stdin rejected:` reply are not read as the user's refusal. A version-15 store re-reads its transcripts at the next deposit.
- `oars gate hook` closes the review lows of the policy and notes release: one name twice in a call is one note and one counted row; a kept registry answer, found or not, is read only in the folder that asked and never for a call with no working directory; a row cut at the hook's own deadline reads as no exposure, since nothing printed; and a call starts at most three helpers, leaving the other names to a later sight. A `block` applies to `not-found` only (an npm name; a Python name never reads `not-found`).
- `oars gate hook` tightens its record: one name twice in a call is one note and one counted row; a kept registry answer, found or not, is read only in the folder that asked and never for a call with no working directory; a row cut at the hook's own deadline reads as no exposure, since nothing printed; and a call starts at most three helpers, leaving the other names to a later sight. A `block` applies to `not-found` only (an npm name; a Python name never reads `not-found`).
- `oars pool fetch` takes `--harness <name>` and the bundle route now carries the harness as a required segment, `/bundle/<harness>/<harnessVersion>/<vocab>`; the `?harness=` query is gone. The signed payload names its harness, and `verifyBundle` refuses a validly signed bundle made for another one. With no flag the fetch asks for the harness your local store holds the most sessions of (claude-code when the store is empty or no harness leads) and prints which it chose and how to change it (`No --harness given: fetching cursor, the harness your local store holds the most sessions of (3 of 4). Pass --harness <name> to fetch another (...)`); only counts are read, and none leave the machine. A name off the list is refused before anything is sent. Bundles are kept per harness (`pool-replica/<server>/<harness>/<version>.json`), so a fetch for one harness never overwrites another's, and `--json` and the text output name the harness.
- `oars pool outbox --explain` now words the `flags` and `program` rows as the deposit sends them (a flag is never the literal placeholder, and a program off the public list goes as `private`), and the pool refuses flags or pulls on a `private` program by field name.
- `oars pool deposit` builds one batch per main session, once the session and its subagents have all been quiet for 6 hours (a session still inside that window builds nothing and any older batch of it is withdrawn): the main run's steps, then each subagent run with its `agentType` and `parent`; one `merkleRoot` and `leaves` per transcript, the main's first; one `timingPrint` over the main run's timed calls (none under 50 of them, and a subagent's calls never join it); and a `remainingTokens` bucket on every step, taken over the exact tokens still to come. A subagent whose main transcript is missing is never a batch. The pool now writes each batch's own tier, the lowest of its transcripts' (`committed` for a claude-code batch with roots, `skeleton` for Cursor, `none` for a root that cannot be real), and rewrites it on a resend, so a claude-code batch with one prompt and one tool step lifts the fetch cap. `oars pool outbox --explain` has a row for every new field.
- `oars pool deposit` no longer sends a step's `seg`, and sends no `parent` link for a subagent that a subagent spawned (a nested spawn has no position in the main run, so a link would name the wrong call). The pool rebuilds `seg` from position and refuses it by name, and refuses the exact-count form (format 1) with that wording. A shown recall beside a flagged call no longer adds a second row to a cell.
- `oars pool deposit` and the local pool read tally a shell step's flags and pulls one cell each, and key a motif on the program and subcommand only, so no cell or motif holds a list longer than one. A cell with a flag keeps its id; the program-and-subcommand cell is new. `usage.thinking` counts as tokens, not as a call. A non-Claude harness's `shell.exec` step is read through the projection without the Claude `SHELL` gate. Skeleton format 2 drops tool `n`, prompt `index`, a step's `edges`, and a transcript's `spawnedIn` (positions replace them, and a nested subagent spawn is not representable), and the bundle's `ETag` and `motifs` follow the asked `harness`.
- `oars pool deposit` sends skeleton format 2: a shell step holds the projected program, subcommand, and flags (a private or snapshot-only program as `private`) in place of the joined frame, usage and step costs are buckets, and `deltas` is empty. The pool refuses the old frame form (format 1) by name. The pool's ingest and the local pool read compute cells in one module, counting a bucketed value as its bucket's lowest value. The bundle route takes `?harness=` (default `claude-code`) and holds only that harness's cells at the version's bucket.
- `oars gate hook` now adds a note about a name first published within 30 days or not found, with no policy file needed; `gate-policy.json` (in the sessions store, written by you) sets each class (`young-name`, `not-found`) to `warn`, `block`, or `off`, with a day count and a holdback share. A note states a registry fact (a name first published within 30 days, or not found after the manager's own configuration answered), and a block is a labeled deny that exists only for `not-found` when you write `block`. A holdback (default 10 percent) withholds notes at random and never a block; each row records its `arm`, the `lineShown`, the `lineHeld`, and the `policy` it ran under. A registry ask the hook has to cut is finished by a detached helper that fills the cache, so the next sight reads it. `oars gate policy` prints the policy in force and `oars gate report` counts the arms and any invalid policy file. A crossing goes nowhere unless you opt in, and no opt-in exists yet. `oars gate install` now sets the mode after writing (the umask no longer masks it), follows a symlink that points at nothing yet, and removes its temp file when the rename fails.
- `oars sessions` capture version 15 corrects two values version 14 stored: a Cargo table header that ends in a comment (`[package] # x`) is now read as a header, so the next `version =` is no longer stored as the dependency `crates:version`, and `packageVersion` keeps only a version of three or four dotted numbers, so `cargo add serde@1` (a range to its registry) and `pip install requests==2.31` (capture cannot tell a short exact pin from a short range) store null. Calls whose `packageVersion` is null share one `first`, so `pip install x==2.31` then `pip install x==2.30` marks `true`, then `false`, where version 14 marked both `true`. A store captured at 14 is behind, and its next deposit captures every transcript again.
- `oars sessions` capture version 14 stores, locally and sending nothing, the `errorCode` class of a failed call, the packages an install or runner call resolves (`<ecosystem>:<name>`, `packageVersion`, a `first` mark) and the dependency names a manifest read or edit shows, and stack strata on the session and prompt records: language with its share bucket, `repoFiles` bucket, framework from packages, and a counted `explore`. The packages, language, and framework have projections that return a list member, `other`, or `private`; the `languageShare` and `repoFiles` projections return nothing for a value outside their list, and `explore` is a count the wire half buckets. A store captured before version 14 is read again on its next deposit.
- A session-end hook deposit that finds the store locked by another deposit no longer leaves its session behind until a whole-store run. After its 3 second wait it records the session in a pending list (`pending/` in the store: one file per deferral holding only the transcript path) and exits as before; the next deposit of any kind, hook or whole-store, deposits the pending sessions first (a hook takes at most 5 per run, a count and not a time limit, and never compacts; an entry that fails 5 times is dropped, since a whole-store run still reaches the transcript). The step log records the refusal as a `deposit` row with the new status `deferred`, so it is no longer counted in `measure`'s failed runs or as a stuck step; `measure` prints it as `deposit@<ev> deferred (store locked)`. No capture or extractor version change. An older oars skips a `deferred` row when it reads the log (docs/sessions-store.md).
- `oars pool login` now runs the provider's device flow (RFC 8628) itself, with Google's `openid` or GitHub's empty scope, and sends the provider's token to the pool once, at `POST /v1/login`, which replaces `/v1/login/start` and `/v1/login/poll`. The pool reads the subject, discards the token, and answers its credential. Every request, to the provider and to the pool, prints (request line, every header, and body) before it is sent, with the device code, the provider's token, and the credential shown only as `<credential: n bytes>`. The client ID and Google's client secret come from `OARS_GITHUB_CLIENT_ID`, `OARS_GOOGLE_CLIENT_ID`, and `OARS_GOOGLE_CLIENT_SECRET`; one that is unset stops the command before it sends anything, and names the variable.
- `oars pool deposit` now writes batches to an outbox and stops: nothing is sent. Each session passes the folder allowlist and the exclusion check before any projection runs, and one that fails either, or has no raw to scan, is counted by reason and never built. The new `oars pool outbox` prints each batch exactly as it would be sent, request line and every header included, with the credential as `<credential: n bytes>`, then its SHA-256, and records that it was shown (`--json`: `deposited` is now `batched`, `tooLarge` is gone, and `excluded.folder`, `withdrawn`, and `discarded` are new); `--explain` adds each field's rule. `oars pool deposit --send <hash>` accepts only a batch that was shown and is unchanged, and reads it again just before the request; sending is disabled in this release, so it stops with `sending_disabled` (exit 5) and no request. Batches built under an older vocabulary or field list are discarded, and `oars sessions verify` reports their count. `oars pool deposit` still refuses with `vocabulary_expired` when this client is more than 30 days past its vocabulary snapshot.
- `oars pool fetch` prints the request line and every header before it sends (credential shown only as `<credential: n bytes>`), keeps the bundle's `ETag` and sends `If-None-Match` so an unchanged bundle is a 304 that keeps the file, and on the weekly cap (429) keeps the bundle, says when to try again, and exits 10 (new: `CAPPED`). It also prints every header it sends, including the `cache-control: no-cache` and `pragma: no-cache` that Node adds to a conditional request.
- `oars pool fetch` now takes `--harness-version <version>` in place of `--stack` and fetches that version's signed bundle from `/bundle/<version>/<vocab>`. Nothing the pool serves is keyed by stack any more. The option is required (there is no default version), `--json` carries `harnessVersion` in place of `stack`, the problem code `slice_unverified` is now `bundle_unverified`, and a bundle of another vocabulary version is refused even when its signature holds.
- The pool counts fetches per account per ISO week (`fetch_cap`, 429 with `Retry-After`) in place of a capped read count, and a bundle carries an `ETag`: a conditional request that still matches gets a 304 and spends no fetch. A bundle no longer has a `capped` field, and `oars pool fetch` no longer prints one. A deposit lifts the cap only when its batch counts toward access.
- `oars gate install` and `oars gate uninstall` wire one fail-open `PreToolUse` hook into Claude Code's user settings, and `oars gate hook` records each package, MCP server, and skill pick as it happens into `crossings.jsonl`, in under a second, with no output and no decision; `oars gate report` counts that one file, once per crossing, whether the hook, a replay, or both saw it. An `npx <name>` whose folder already holds `node_modules/.bin/<name>` is now recorded as `local-bin-run`, not `fetch-and-run`.
- `oars sessions` capture version 13: the email mask keeps a plain dotted version after `npm:` or `jsr:` (a prerelease or a four-part numeric tail stays masked; a pinned alias such as `foo@npm:bar@1.0.0` keeps its pick, and a pull of an npm alias names the real package); a block word in another case, or a wrapper in another case or by path (`IF`, `TIMEOUT 5`, `/usr/bin/timeout 5`), is skipped to reach the real program; and a program whose basename holds a space is stored as `<literal>` in `segments`. A program read at the 30-character cut projects `private` instead of a listed name it may only begin. The same re-read settles the two stored forms of a `copilot` shell step (`copilot`, not `<literal>`). A store captured at 12 is behind, and its next deposit captures every transcript again.
- `oars sessions deposit` and `verify` use less memory on a large store: the log is read in two passes that keep only each session's highest `rev`, the newer-captures check keeps a number per session instead of loading the store, and `verify` reads skeletons without their content hashes. On a test store whose log holds superseded records, a `deposit` that skips unchanged files needs a 104 MB heap instead of 168 MB and `verify` 248 MB instead of 336 MB; on a settled log the gain is 4 to 8 percent. The full load a deposit made first to check for newer captures is gone; a deposit that re-captures every transcript measured 731 and 551 MB of RSS before and 501 and 531 MB after at 800 sessions (two runs each, so within noise), and its least heap at 400 sessions was 104 and 120 MB in two runs of the new build against 112 MB in one of the old, so no gain is shown for a recapture at this bisect step. A store too large for node's default heap still needs `NODE_OPTIONS=--max-old-space-size=<MB>` (docs/sessions-store.md, Memory).
- `oars sessions` ships a pinned public vocabulary (`VOCAB_VERSION` 1, snapshot of 2026-11-04, `packages/cli/vocab/`, about 6.2 MB raw and 1.1 MB gzipped in the package) and the functions that project the fields a future pool would carry (they compute from the store and write nothing to disk). A shell call projects to `program`, `subcommand`, and `flags` from that program's list, so `grep AcmeWidgetMerger` is `grep` alone; a program, package, tool, or skill outside the vocabulary is `private`, `custom`, or only a count, and a command the parser cannot read is `private`. Nothing uploads, and `oars pool deposit` does not call the projection yet. A client more than 30 days past its snapshot builds no batch, and `node packages/cli/scripts/vocab-snapshot.mjs` regenerates the snapshots. The session store moves to extractor version 11, which classes raw `agentType`, `keys`, and `frameId` with the joined frame as account-store-only (class A); the deposit skeleton still sends the joined frame until a later release. Your store re-derives on its next deposit with nothing re-read from transcripts.
- `oars gate` reads more exactly before the hook records live: names behind `bun create`, `python -m pipx` and `python -m uv`, `pnpx`, PEP 508 and package-manager protocol words, percent-encoded dots, and `skills add` shapes; a name is not sent to a registry when `HOME`, `XDG_CONFIG_HOME`, `sudo`, a sourced file, `Set-Item Env:`, `SetEnvironmentVariable`, `npm config set`, or a venv's `activate` could change its config (and `pnpm` is never asked), and a replay without `--registry-state` no longer writes back a kept answer for such a name; `uv run pip install x` now reads as a crossing under `uv`, so a registry question refuses it; a version holding a character such as `#`, `&`, `?`, `;`, or `%`, or a space and a word of prose, now counts as `unreadable-name` instead of being recorded; a resumed transcript no longer counts a call twice; `program` is a closed list (`PROGRAMS`), and `--allow codex` says what it does not read.
- The pool serves a cell or read only at 5 accounts (`K_CELL`, up from 3), and a `live` read's floor counts only the sliced day's accounts: its `inputs` no longer cite the baseline cells, and a baseline under the floor on its own is `null`.
- `oars sessions`: the sessions docs now say that a crashed session's checkpoint may hold per-model totals that are not read.
- `oars sessions` capture version 11: the part of an MCP tool name after `mcp__` (Cursor: `mcp_`) is redacted wherever it is stored, package-manager and shell command forms are read more exactly (`pulls`, `segments`, `commits`, `steps`), and a typed line that only starts with an injected tag's name now opens a prompt. The next `deposit` captures every transcript again.
- `oars sessions` now records, per session and from the transcript only, the setup it ran with (permission mode, plugins, hook count, and instruction bytes), the tool funnel (tools offered, loaded, and removed), and the trust shape (interrupts, rejections, policy denials, and minutes the agent ran between human turns), as counts, names, and sizes; Codex and Copilot record the fields their transcripts hold, and Cursor none. The capture version moves to 12, so the next `oars sessions deposit` reads every transcript again.
- A deposit whose read of its own `store.lock` is refused at the end (an antivirus share violation on Windows) now removes the lock (retrying a share violation, and never losing the deposit's result if the removal is refused too) instead of leaving it for the 10-minute stale window, and a revert file of a Codex thread that a crash tore no longer makes the whole thread unreadable.
- `oars sessions exclusions` is new: it scans your sessions against a local term file (`OARS_EXCLUSION_TERMS`) and writes the excluded ones to a list, printing counts only. `oars sessions gold sample`, published in 0.3.0, now refuses a draw with no term file, and `--exclude-term` only adds to that file's terms instead of replacing it.
- A store lock whose holder hangs is no longer kept for good: the holder refreshes it for at most an hour; once it has aged 10 more minutes, the next deposit breaks it and prints one line naming the holder's pid.
- `oars keys create|list|revoke` manages your API keys. `keys create --workload <id>` mints a key limited to one workload (authorities `AGENT_OPERATE` and `AGENT_READ` only), so a scheduled agent can change its own schedule without being able to spend or reach another workload. The `make-me-money` skill shows the recipe.

## 0.3.0

- `oars sessions` keeps a local, deterministic memory of your own Claude Code sessions (and, with `--allow cursor`, Cursor sessions): `deposit`, `recall`, `books`, `measure`, `verify`, and an MCP server (`recall --mcp`), plus `gold sample`, `gold arms`, and `gold score`. oars makes no model call and no network call, except `gold arms`, which sends redacted text through your own Claude subscription.
- `oars sessions hook install` writes three fail-open hooks (`SessionStart`, `PostToolUseFailure`, `SessionEnd`) into a Claude Code settings file; `hook status` lists them and `hook uninstall` removes only the entries install wrote. Install is idempotent, and raises `cleanupPeriodDays` in that file to at least 365 (uninstall leaves it raised). `--schedule nightly` registers a daily deposit task on Windows.
- Every deposited transcript is also hard-linked (copied across volumes) into `<config>/oars/sessions/raw/`, on by default, so it outlives Claude Code's own cleanup. These are raw transcripts on your machine, and the files themselves are not uploaded.
- `oars purchasing` is hidden from `--help` and refuses with "Paid agents are not open yet" unless `OARS_ISSUER_URL` names a platform of your own; it never reads the launch flag.
- `oars login` with the built-in issuer not answering discovery (no answer, an error status, or a body that is not discovery JSON) now exits 2 with the not-launched message instead of exit 8 or 1; a failure on `--issuer-url` or `OARS_ISSUER_URL` keeps its current error.
- `verify` and `books` name the project folders that hold transcripts but are not on the saved allowlist, which are never read (`scope` in `verify --json` and `books --json`); the list never fails `verify --strict`.
- `verify` audits each session against its raw file (raw-file match, Merkle root, count bindings); it also reports every session on its own and scores each against your own other weeks on its harness (`selfBaseline`).

  unreachable catalog exits 8, before anything is registered.
