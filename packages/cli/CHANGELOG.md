# Changelog

All notable changes to `@manyoars/oars`. Versions follow semver; a release is the tag `cli-v<version>`.

## Unreleased

- `oars pool deposit` and the local pool read tally a shell step's flags and pulls one cell each, and key a motif on the program and subcommand only, so no cell or motif holds a list longer than one. A cell with a flag keeps its id; the program-and-subcommand cell is new. `usage.thinking` counts as tokens, not as a call. A non-Claude harness's `shell.exec` step is read through the projection without the Claude `SHELL` gate. Skeleton format 2 drops tool `n`, prompt `index`, a step's `edges`, and a transcript's `spawnedIn` (positions replace them, and a nested subagent spawn is not representable), and the bundle's `ETag` and `motifs` follow the asked `harness`.
- `oars pool deposit` sends skeleton format 2: a shell step holds the projected program, subcommand, and flags (a private or snapshot-only program as `private`) in place of the joined frame, usage and step costs are buckets, and `deltas` is empty. The pool refuses the old frame form (format 1) by name. The pool's ingest and the local pool read compute cells in one module, counting a bucketed value as its bucket's lowest value. The bundle route takes `?harness=` (default `claude-code`) and holds only that harness's cells at the version's bucket.
- `oars sessions` capture version 14 stores, locally and sending nothing, the `errorCode` class of a failed call, the packages an install or runner call resolves (`<ecosystem>:<name>`, `packageVersion`, a `first` mark) and the dependency names a manifest read or edit shows, and stack strata on the session and prompt records: language with its share bucket, `repoFiles` bucket, framework from packages, and a counted `explore`. The packages, language, and framework have projections that return a list member, `other`, or `private`; the `languageShare` and `repoFiles` projections return nothing for a value outside their list, and `explore` is a count the wire half buckets. A store captured before version 14 is read again on its next deposit.
- A session-end hook deposit that finds the store locked by another deposit no longer leaves its session behind until a whole-store run. After its 3 second wait it records the session in a pending list (`pending/` in the store: one file per deferral holding only the transcript path) and exits as before; the next deposit of any kind, hook or whole-store, deposits the pending sessions first (a hook takes at most 5 per run, a count and not a time limit, and never compacts; an entry that fails 5 times is dropped, since a whole-store run still reaches the transcript). The step log records the refusal as a `deposit` row with the new status `deferred`, so it is no longer counted in `measure`'s failed runs or as a stuck step; `measure` prints it as `deposit@<ev> deferred (store locked)`. No capture or extractor version change. An older oars skips a `deferred` row when it reads the log (docs/sessions-store.md).
- `oars pool login` now runs the provider's device flow (RFC 8628) itself, with Google's `openid` or GitHub's empty scope, and sends the provider's token to the pool once, at `POST /v1/login`, which replaces `/v1/login/start` and `/v1/login/poll`. The pool reads the subject, discards the token, and answers its credential. Every request, to the provider and to the pool, prints (request line, every header, and body) before it is sent, with the device code, the provider's token, and the credential shown only as `<credential: n bytes>`. The client ID and Google's client secret come from `OARS_GITHUB_CLIENT_ID`, `OARS_GOOGLE_CLIENT_ID`, and `OARS_GOOGLE_CLIENT_SECRET`; one that is unset stops the command before it sends anything, and names the variable.
- `oars pool fetch` prints the request line and every header before it sends (credential shown only as `<credential: n bytes>`), keeps the bundle's `ETag` and sends `If-None-Match` so an unchanged bundle is a 304 that keeps the file, and on the weekly cap (429) keeps the bundle, says when to try again, and exits 10 (new: `CAPPED`). It also prints every header it sends, including the `cache-control: no-cache` and `pragma: no-cache` that Node adds to a conditional request.
- `oars pool fetch` now takes `--harness-version <version>` in place of `--stack` and fetches that version's signed bundle from `/bundle/<version>/<vocab>`. Nothing the pool serves is keyed by stack any more. The option is required (there is no default version), `--json` carries `harnessVersion` in place of `stack`, the problem code `slice_unverified` is now `bundle_unverified`, and a bundle of another vocabulary version is refused even when its signature holds.
- The pool counts fetches per account per ISO week (`fetch_cap`, 429 with `Retry-After`) in place of a capped read count, and a bundle carries an `ETag`: a conditional request that still matches gets a 304 and spends no fetch. A bundle no longer has a `capped` field, and `oars pool fetch` no longer prints one. A deposit lifts the cap only when its batch counts toward access; until a wire carries a root, a claude-code batch does not.
- `oars gate install` and `oars gate uninstall` wire one fail-open `PreToolUse` hook into Claude Code's user settings, and `oars gate hook` records each package, MCP server, and skill pick as it happens into `crossings.jsonl`, in under a second, with no output and no decision; `oars gate report` counts that one file, once per crossing, whether the hook, a replay, or both saw it. An `npx <name>` whose folder already holds `node_modules/.bin/<name>` is now recorded as `local-bin-run`, not `fetch-and-run`.
- `oars sessions` capture version 13: the email mask keeps a plain dotted version after `npm:` or `jsr:` (a prerelease or a four-part numeric tail stays masked; a pinned alias such as `foo@npm:bar@1.0.0` keeps its pick, and a pull of an npm alias names the real package); a block word in another case, or a wrapper in another case or by path (`IF`, `TIMEOUT 5`, `/usr/bin/timeout 5`), is skipped to reach the real program; and a program whose basename holds a space is stored as `<literal>` in `segments`. A program read at the 30-character cut projects `private` instead of a listed name it may only begin. The same re-read settles the two stored forms of a `copilot` shell step (`copilot`, not `<literal>`). A store captured at 12 is behind, and its next deposit captures every transcript again.
- `oars sessions deposit` and `verify` use less memory on a large store: the log is read in two passes that keep only each session's highest `rev`, the newer-captures check keeps a number per session instead of loading the store, and `verify` reads skeletons without their content hashes. On a test store whose log holds superseded records, a `deposit` that skips unchanged files needs a 104 MB heap instead of 168 MB and `verify` 248 MB instead of 336 MB; on a settled log the gain is 4 to 8 percent. The full load a deposit made first to check for newer captures is gone; a deposit that re-captures every transcript measured 731 and 551 MB of RSS before and 501 and 531 MB after at 800 sessions (two runs each, so within noise), and its least heap at 400 sessions was 104 and 120 MB in two runs of the new build against 112 MB in one of the old, so no gain is shown for a recapture at this bisect step. A store too large for node's default heap still needs `NODE_OPTIONS=--max-old-space-size=<MB>` (docs/sessions-store.md, Memory).
- `oars sessions` ships a pinned public vocabulary (`VOCAB_VERSION` 1, snapshot of 2026-11-04, `packages/cli/vocab/`, about 6.2 MB raw and 1.1 MB gzipped in the package) and the functions that project the fields a future pool would carry (they compute from the store and write nothing to disk). A shell call projects to `program`, `subcommand`, and `flags` from that program's list, so `grep AcmeWidgetMerger` is `grep` alone; a program, package, tool, or skill outside the vocabulary is `private`, `custom`, or only a count, and a command the parser cannot read is `private`. Nothing uploads, and `oars pool deposit` does not call the projection yet. A client more than 30 days past its snapshot builds no batch, and `node packages/cli/scripts/vocab-snapshot.mjs` regenerates the snapshots. The session store moves to extractor version 11, which classes raw `agentType`, `keys`, and `frameId` with the joined frame as account-store-only (class A); the deposit skeleton still sends the joined frame until the next pool brief. Your store re-derives on its next deposit with nothing re-read from transcripts.
- `oars gate` reads more exactly before the hook records live: names behind `bun create`, `python -m pipx` and `python -m uv`, `pnpx`, PEP 508 and package-manager protocol words, percent-encoded dots, and `skills add` shapes; a name is not sent to a registry when `HOME`, `XDG_CONFIG_HOME`, `sudo`, a sourced file, `Set-Item Env:`, `SetEnvironmentVariable`, `npm config set`, or a venv's `activate` could change its config (and `pnpm` is never asked), and a replay without `--registry-state` no longer writes back a kept answer for such a name; `uv run pip install x` now reads as a crossing under `uv`, so a registry question refuses it; a version holding a character such as `#`, `&`, `?`, `;`, or `%`, or a space and a word of prose, now counts as `unreadable-name` instead of being recorded; a resumed transcript no longer counts a call twice; `program` is a closed list (`PROGRAMS`), and `--allow codex` says what it does not read.
- The pool serves a cell or read only at 5 accounts (`K_CELL`, up from 3), and a `live` read's floor counts only the sliced day's accounts: its `inputs` no longer cite the baseline cells, and a baseline under the floor on its own is `null`.
- `oars sessions`: the sessions docs now say that a crashed session's checkpoint may hold per-model totals that are not read.
- `oars sessions` capture version 11: the part of an MCP tool name after `mcp__` (Cursor: `mcp_`) is redacted wherever it is stored, package-manager and shell command forms are read more exactly (`pulls`, `segments`, `commits`, `steps`), and a typed line that only starts with an injected tag's name now opens a prompt. The next `deposit` captures every transcript again.
- `oars sessions` now records, per session and from the transcript only, the setup it ran with (permission mode, plugins, hook count, and instruction bytes), the tool funnel (tools offered, loaded, and removed), and the trust shape (interrupts, rejections, policy denials, and minutes the agent ran between human turns), as counts, names, and sizes; Codex and Copilot record the fields their transcripts hold, and Cursor none. The capture version moves to 12, so the next `oars sessions deposit` reads every transcript again.
- A deposit whose read of its own `store.lock` is refused at the end (an antivirus share violation on Windows) now removes the lock (retrying a share violation, and never losing the deposit's result if the removal is refused too) instead of leaving it for the 10-minute stale window, and a revert file of a Codex thread that a crash tore no longer makes the whole thread unreadable.
- `oars sessions exclusions` is new: it scans your sessions against a local term file (`OARS_EXCLUSION_TERMS`) and writes the excluded ones to a list, printing counts only. `oars sessions gold sample`, published in 0.3.0, now refuses a draw with no term file, and `--exclude-term` only adds to that file's terms instead of replacing it.
- A store lock whose holder hangs is no longer kept for good: the holder refreshes it for at most an hour; once it has aged 10 more minutes, the next deposit breaks it and prints one line naming the holder's pid.
- `oars keys create|list|revoke` manages your API keys. `keys create --workload <id>` mints a key limited to one workload (authorities `AGENT_OPERATE` and `AGENT_READ` only), so a scheduled agent can change its own schedule without being able to spend or reach another workload. The `make-me-money` skill shows the recipe.

## 0.3.0

- `oars sessions` keeps a local, deterministic memory of your own Claude Code sessions (and, with `--allow cursor`, Cursor sessions): `deposit`, `recall`, `books`, `measure`, `verify`, and an MCP server (`recall --mcp`), plus `gold sample`, `gold arms`, and `gold score`. oars makes no model call and no network call, except `gold arms`, which sends redacted text through your own Claude subscription.
- `oars sessions hook install` writes three fail-open hooks (`SessionStart`, `PostToolUseFailure`, `SessionEnd`) into a Claude Code settings file; `hook status` lists them and `hook uninstall` removes only the entries install wrote. Install is idempotent, and raises `cleanupPeriodDays` in that file to at least 365 (uninstall leaves it raised). `--schedule nightly` registers a daily deposit task on Windows.
- Every deposited transcript is also hard-linked (copied across volumes) into `<config>/oars/sessions/raw/`, on by default, so it outlives Claude Code's own cleanup. These are raw transcripts on your machine, and the files themselves are not uploaded.
- `oars purchasing` is hidden from `--help` and refuses with "Paid agents are not open yet" unless `OARS_ISSUER_URL` names a platform of your own; it never reads the launch flag.
- `oars login` with the built-in issuer not answering discovery (no answer, an error status, or a body that is not discovery JSON) now exits 2 with the not-launched message instead of exit 8 or 1; a failure on `--issuer-url` or `OARS_ISSUER_URL` keeps its current error.
- `verify` and `books` name the project folders that hold transcripts but are not on the saved allowlist, which are never read (`scope` in `verify --json` and `books --json`); the list never fails `verify --strict`.
- `verify` audits each session against its raw file (raw-file match, Merkle root, count bindings); it also reports every session on its own and scores each against your own other weeks on its harness (`selfBaseline`).

## 0.2.0

- `oars templates` lists the starter templates, and `oars deploy --template <id>` deploys one without an image of your own.
- `oars login` works with no flags once Many Oars has launched: the production issuer is built in, and
  `https://manyoars.com/.well-known/oars.json` (`{"launched": true}`) switches it on. The flag never supplies the URL.
  Before launch, `login` says "Many Oars has not launched yet: pass --issuer-url or set OARS_ISSUER_URL." and exits 2.
  `--issuer-url` and `OARS_ISSUER_URL` still win.
- An exit 6 ends with a "Needs you:" line that names the link for the step only a person can do, such as Stripe onboarding.
- `deploy` refuses a mix of flags with a message that uses the serial comma; a `--template` the catalog lacks exits 2 and an
  unreachable catalog exits 8, before anything is registered.
