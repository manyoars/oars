# Changelog

All notable changes to `@manyoars/oars`. Versions follow semver; a release is the tag `cli-v<version>`.

## Unreleased

- `oars card` no longer counts more active days than its window has days. A 30-day window runs 30 x 24 hours from now, so it could touch 31 UTC dates and say "31 active days"; the count is now capped at the window's days.
- `oars card --no-cost` leaves the cost row out of the picture, the `--text` table, and the `--json` card, so you can share a card without your spend. The picture is one row shorter and nothing else changes. Without the flag the card is as before.
- Erasing an account now keeps each Deposit's anonymous shape (closed lists, buckets, listed names, tool shapes, and step order) instead of a bare marker, drops every identifying, joinable, or free-text leaf, and cuts the times on the kept rows to the Monday of their ISO week (`docs/pool.md`, "Erasure"). Deposits erased before this hold the marker only and cannot be rebuilt.
- `erase account` now unlinks the rows it keeps (covenant 6.6(d); `docs/pool.md`, "Erasure"): the account's `machines` and `deposits` move to one random `erased:` id per erasure (no key, so nothing recomputes it from a GitHub id), a machine's id, a deposit's session id and ingest mark, and the machine's key hashes are replaced with random values, its fingerprint is blanked, the machine is revoked, the counting, machine, and expiry times are cut to the UTC day (now the Monday of the ISO week, see the bullet above), each raw object's stored date to the UTC day, the rows move to random negative rowids, those rows carry no erasure date, and `accounts.provider_created` is cleared. Only the acceptance and sign-in records, the tombstones, the audit, and the hash, size, and date of each raw object keep the account id. A rerun is a no-op; rerun `erase account --confirm` for each account already erased.
- Telemetry is off, with no prompt, on a machine whose time zone is in the EU, the EEA, or the UK (an unresolvable zone counts as closed), and the first-run notice now states the Usage Data license (the covenant's sentences) instead of "and nowhere else". Each batch carries `notice`, the notice version (2); a batch without it is not licensed (`docs/flags.md`, `docs/pool.md`). The first-run event is recorded once per install: an install that saw an older notice sees the new one but records no second `first-run`. The README telemetry section names the closed regions and the Usage Data license.

Every Edit, MultiEdit, and Write call keeps a digest of its old and new text (the first 32 hex digits of the SHA-256 of the exact text; a Write keeps a new digest only), and a `git restore <path>` or `git checkout -- <path>` keeps the path it names. The consequence reading of a recall classes a later edit that swaps an earlier edit's old and new text, a Write that repeats an earlier Write's text after a different Write, and a `git restore` of an edited path as a reversion, beside the commit-sha form. - A call's name-like tokens reach the pool under wire format 5 (`CAPTURE_VERSION` 33, field list 10; the pool still reads formats 3 and 4, and the next deposit captures every transcript again). A call carries `names`, the file, directory, and variable names its values held, flag values that are names, and a custom agent's name, each with its kind, plus `namesDropped`, a bucket of how many tokens were not sent. Names are sent as written with no count threshold, so a folder called `ledger-core` goes to the pool as `ledger-core`; a folder above the session root (usually your account name) is never read, and neither is the value after `--token`, `--password`, `--secret`, or `--api-key`. A name your exclusion terms or the secret-shape check match, or that is not a single word, is dropped and counted. A double-quoted value joined to a flag or an assignment is read as its unquoted form (`--region="eu"` and `API_REGION="eu"` are read as `--region=eu` and `API_REGION=eu`). No argument text or path is sent; commands go only as templates (below). Nothing is served from a name yet (`docs/pool.md`).
- A shell call's commands reach the pool as templates under wire format 5 (`CAPTURE_VERSION` 34, field list 13; the next deposit captures every transcript again). A call carries `templates`, one per command in the order they run: its program's base name in lower case, without a Windows launcher suffix, its subcommand where the program's own public list has one, and its flags that are on the public list or one letter, as written, and every other word as a slot (`<text>`, `<path>`, `<ident>`, `<num>`, `<url>`, `<var>`, `<flag>`), so `git commit -m "fix the login bug"` is `git commit -m <text>` and `pytest tests/test_login.py` is `pytest <path>`. The word after a credential or text flag (`--token`, `--api-key`, `-m`) or any other one-letter flag (but `-k` on pytest), apart or joined, is always `<text>` or goes inside `<flag>`. A template whose program, subcommand, or flag the redactor changes, an exclusion term matches, or that is not a name is dropped whole and counted in `templatesDropped`. No argument is sent, and the pool stores the field and keys no cell on it. A call that edits a file carries `diffShape` the same way: a sorted set from a closed list (`import-added`, `import-removed`, `identifier-renamed`, `lines-added`, `lines-removed`, `lines-changed`, `whitespace-only`, `file-written`), read on your machine from the old and new text, so replacing `total` with `subtotal` in a line sends `identifier-renamed` and none of the text.
- A recommendation's exposure now survives the deposit under wire format 6 (field list 12; the pool still reads formats 3, 4, and 5): the batch carries each recommendation of the session (its id, whether it was shown or held back, the pool version it answered from, and a window of calls), never the query, the text shown, or the evidence. The pool stores a cell's exposure as `shown`, `held`, or `unknown` (migration 0021, `docs/pool.md`, "Cell grain and effort"); a session with no row reads `unknown`, never unexposed, and every row stored before reads `unknown`. The pool checks a batch's `recoveryCalls` by the rule of the batch's own format, so a client already released is not refused for a failed edit.

Each run rechecks every enrolled repository against GitHub (a repository that is public now, or whose record cannot be read, is refused with none of its branches fetched), reads branch tips only, and refuses and reports, with nothing written and the branch left in place, a branch whose machine is not in `machines.jsonl`, whose `terms` digest is not the keyed digest of this machine's own exclusion terms, whose file holds a field off the batch field list, its own `claimed`, a value off a closed list, an `id` unlike its branch, or one of your exclusion terms, or whose `stamp` is not a stamp folder for its vocabulary. Each session passes the folder allowlist and the exclusion check before any projection runs; one that fails either is counted by reason and never built, and a session that later fails a gate has its earlier batch removed. The batch also carries your own before and after windows as `deltas` (a plugin added or removed as `private`, a `permissionMode` or `effort` changed by field name alone, or a public package removed; 7 days each, at least 5 sessions a side, marked once in `deltas-sent.log`). A batch built under an older vocabulary or field list is rebuilt, and the older file removed. `oars pool outbox` prints each batch exactly as it would be sent, then its SHA-256, and records that it was shown; `--explain` adds each field's rule. `--json` carries `batched`, `excluded.folder`, `withdrawn`, and `discarded`.
- `oars pool fetch --harness-version <version>` fetches that version's signed bundle for one harness (`--harness <name>`; with no flag, the harness your local store holds the most sessions of, claude-code when none leads, and it prints which it chose and how to change it; only counts are read, and none leave the machine), verifies it against the key pinned at login, and keeps it per harness (`pool-replica/<server>/<harness>/<version>.json`). It checks the sign-in before it reads the local store, prints every request line and header before sending (credential shown only as `<credential: n bytes>`), keeps the bundle's `ETag` and sends `If-None-Match` so an unchanged bundle is a 304 that keeps the file, and on the weekly cap (429) keeps the bundle, says when to try again, and exits 10 (`CAPPED`). A bundle of another vocabulary version, or made for another harness, is refused even when its signature holds (`bundle_unverified`).
- `oars login` with the built-in issuer not answering discovery (no answer, an error status, or a body that is not discovery JSON) exits 2 with the not-launched message instead of exit 8 or 1; a failure on `--issuer-url` or `OARS_ISSUER_URL` is still reported as that failure, with its own exit code. A request the network refuses (exit 8) now names the server and the network's reason (`Cannot reach the server at https://api.manyoars.com: getaddrinfo ENOTFOUND api.manyoars.com`) in place of `Cannot reach the server: fetch failed`; an `OAUTH_TIMEOUT` does not name the server.
